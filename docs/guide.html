城の使い方

城は既存のシステムを置き換えません。販売管理・勤怠・会計の外側に、薄い横串を1枚かけるだけです。
各システムはそのまま動かし続け、城はその出力を受けて、形を揃えて、繋ぎます。

1. 毎日やること ── ありません

取り込みは自動です。人がやることは何もありません。

  1. ベンダーが、決めた名前で共有フォルダ（instance/incoming/）にCSVを置く
  2. 見張りが毎朝それを拾い、種類を判定して取り込み、画面まで作り直す
intake.bat            決まった時刻に、これだけを呼ぶ（タスクスケジューラ）
python castle/app/intake.py --dry-run    取り込まず、何をするつもりかだけ言う
python castle/app/intake.py --freshness  どこまで届いているかを見る

あとは経営ステータスを開くだけです。開くたびにその場で作り直すので、 いつ見ても最新になっています。

届かなかったときに気づけます。画面のいちばん上に「データの届き具合」を置いてあり、 遅れているサイロは赤で名指しします。
自動にするほど「今日も動いたはず」と思い込むもので、 黙って古い数字が出続けるのがいちばん危ないためです。
受入仕様にない名前のファイルは推測で取り込まず、保留へ回します （種類を当てにいくと、間違った種類のまま記録に入ります）。
ファイルを揃える必要はありません。文字コードも、日付の書き方も、部門名の表記も、 並び順も、ベンダーごとに違ったままで構いません。揃えるのが城の仕事です。
同じファイルを二度取り込んでも、記録は増えません（上書きされます）。

2. 月初にやること（1分）

会計が前月を締めたら、部門別損益のCSVを同じ場所に置いて取り込みます。 これで粗利が実績に切り替わります。

python castle/app/import_csv.py --kind 売上原価 instance/incoming/C社*.csv

締まっていない当月は、直近の確定月の原価率を当てた推定です。画面の一番上にそう書いてあります。

3. 現場に書いてもらうこと

ダッシュボードは「どの部門が、どれだけ落ちたか」までしか出せません。 「なぜ」は現場にしかありません。それを書く場所が申し送りです。

  • 落ち込みが出た部門の担当者が、気づいた時点で1〜2行書く
  • 書いたものは、その部門の要確認欄にそのまま並びます
  • 後から書き換えられません。訂正は新しく書き足してください

書き方のコツ

弱い書き方効く書き方
売上が落ちています数量減は意図的。相場高で赤字取引を止めている。8月下旬に戻る見込み
忙しかったです盆前で休業の得意先が増え、1ルートの納品件数が落ちた。臨時要員は入れていない

「見込み」と「打った手」を書くと、読む側が判断できます。 状況だけだと、結局その部門に聞き直すことになります。

4. 打ち手 ── 足りない分を、どう埋めるか

不足額を出すだけでは、読んだあとに何も起きません。埋め方まで置きます。

画面は「売上を1%動かせば営業利益がいくら動くか」という目盛り（レバー）を出します。 そこから先 ── どれが現実的か、誰がいつまでにやるか ── は人が決めます。 判断の材料は機械、判断は人です。

打ち手に書くこと

  • 部門と動かすもの（売上／粗利率／人件費／その他販管費）
  • 何をするか ── 動詞で書きます（200字まで）
  • いくら見込むか ── 人が入れます。機械は推定しません
  • 誰が・いつまでに

状態を進める

仕込み中 → 実行中 → 効果測定中 → 効いた／効かなかった。 効いたものは、いくら効いたかまで戻します。

見込みに数えないものが3つあります。
期限が過ぎて動いていないもの ── 赤で名指しします。台帳がいちばん腐るのはここで、 放っておくと「打ったつもり」が溜まります。
効かなかったもの ── 効くと決まっていないものを足して着地を語れば、粉飾と同じ形になります。
効いたもの ── 効果はもう実績に出ています。見込みにも足せば、二重に数えることになります。

5. 知識の泉 ── 数字と並ぶ、もう一本の泉

数字の泉が出すのは「何が起きたか」。知識の泉に貯めるのは 「この会社で、繰り返し効くこと」です。判断、うまくいかなかった改善、 現場の小さなコツ、新人が知らない前提。

申し送りは流れるもの、知識は残るものと考えてください。 「この件、また来年も同じことが起きるな」と思ったら、それは知識です。

書くときの3つの約束

約束なぜ
本質は一行（120字） 一行で書けないものは、まだ2つ以上が混ざっています。分けて2件にしてください。 ここが緩むと、後から誰も引けない読み物になります。
「なぜ」を必ず書く 理由の無い知識は、状況が変わったときに捨ててよいか判断できません。 永久に残り続けて、判断を狂わせます。
「どう使うか」を必ず書く 次に同じ場面が来たときの行動が書いていないと、ただの感想です。

古くなった知識は、覆す

方針が変わったら、書き換えるのではなく「これを覆す」を押して新しく書きます。 古い方は現役から外れますが、消えません。なぜ覆ったかが、いちばんの学びだからです。

180日だれも見直していない知識は、画面の上で名指しされます。 まだ有効なら「まだ有効」を押してください。 古い知識が現役の顔をしているのが、いちばん危険です。

探しに行かなくていい

知識は部門に紐づいています。その部門の数字が落ちた瞬間、 経営ステータスの要確認欄に、その部門の知識が並びます。 必要な瞬間にだけ出てくるので、普段は忘れていて構いません。

さがす

表記は気にしなくて構いません。 「くらうど」「kuraudo」「ｸﾗｳﾄﾞ」「ＣＬＯＵＤ」── どれで打っても同じものに当たります。

6. アクセスキー（人の出入り）

城はパスワードを作らせません。管理者がアクセスキーを発行して渡す方式です。

python castle/app/users.py --add    "農産部長 田中"
python castle/app/users.py --list
python castle/app/users.py --revoke "農産部長 田中"
  • 平文のキーは発行したその画面にしか出ません。控え損ねたら同じ名前で発行し直します（古いキーは失効します）
  • 保存されているのはハッシュだけです。ファイルが漏れても、それだけでは入れません
  • 異動・退職のときは --revoke で即座に切れます
  • キーは各自のものです。貸し借りすると、記録に残る名前が実際の入力者とずれます
instance/users.json があるかどうかで認証が入り切りします。 無ければ認証なし（自分のPCだけで使う状態）。有れば全員にキーが要ります。

7. 控え（バックアップ）

データは instance/data.db の1ファイルです。控えは1コマンドで取れます。

python castle/app/backup.py                 控えを取る
python castle/app/backup.py --list          一覧
python castle/app/backup.py --restore <ファイル> --yes   戻す
  • 取った直後に開き直して、件数と整合性を確かめてから「取れた」と表示します
  • サーバが動いたままでも、取りこぼしなく取れます
  • 戻す直前に、いまのDBが自動で退避されます。間違った控えを戻しても、そこから戻れます
  • 戻す・古い控えを消す、は --yes が無ければ実行しません

置き場は instance/backups/ です。別のディスクか共有フォルダにも複製してください。 同じPCの中にしかない控えは、PCが壊れた日にいっしょに消えます。

8. 困ったとき

起きたことどうするか
取り込みで
「部門が対応表にない」と出た		 正しい動きです（捨てずに報告しています）。合計行なら放っておいて構いません。 本物の部門なら instance/config.json の aliases にその表記を足します。
数字が古い CSVを置き直して取り込みます。取り込みの履歴は import_csv.py --list で見られます。
間違ったファイルを取り込んだ import_csv.py --undo <番号> で取り消せます。 ただし上書きした分は前の値に戻らないので、正しいCSVを入れ直してください。
サーバが起動しない 同じポートで既に動いていないか確認してください。 --port 8766 のように変えても動きます。
全部おかしくなった 控えから戻します。取り込み元のCSVが残っていれば、 verify.py で作り直すこともできます。

9. この城が、やらないこと

  • 判断しません。数字と内訳と確認すべきことまでを並べます。決めるのは人です
  • 勝手に何かを送りません。メールも発注も行いません
  • 取り消せない操作を自動でやりません。削除・復旧・外部への公開は、必ず人が明示します
  • 既存システムを置き換えません。各ベンダーのシステムはそのまま使い続けます
