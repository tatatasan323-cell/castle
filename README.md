# 城 ── 汎用の社内プラットフォーム

**会社の数字が繋がらないのは、どのシステムも悪くないからです。誰も「間」を担当していないだけ。**

販売管理・勤怠・会計。3つのシステムはそれぞれ正しく動いているのに、
役員会議のたびに担当者がCSVを落とし、Excelで突き合わせて表を作っている。
城は、その既存システムを**置き換えません**。サイロの外側に、薄い横串を1枚かけるだけです。

- **動く画面（架空データのデモ）** → https://tatatasan323-cell.github.io/castle/
- 設計の判断と、その理由 → [DESIGN.md](DESIGN.md)
- note連載「AI内製化の羅針盤」の成果物です

## 何ができるか

| | |
|---|---|
| **数字の泉** | 3サイロを繋いで、部門別の人時生産性（粗利ベース）を1枚に。落ち込みを検知し、売上・粗利率・人時のどこが動いたかまで分解する |
| **知識の泉** | 判断・失敗・コツ・前提を、引ける形で貯める。その部門の数字が落ちた瞬間、同じ画面に出る |
| **申し送り** | 「なぜ落ちたか」は現場にしかない。それを書く口 |

**Python標準ライブラリだけで動きます。** 外部ライブラリもCDNもゼロ。
JavaScriptも使っていません（グラフはサーバ側でSVGごと書き出し）。
データはSQLiteの1ファイル。検査は `python castle/app/verify.py` 一本で90項目。

## 入っているデータについて

**このリポジトリに実在の企業のデータは一切ありません。**
デモは「架空食品商事株式会社」という実在しない会社のもので、
`instance/make_sample.py` がその場で生成します。

```bash
python instance/make_sample.py
```

社内のデータ側（`instance/data.db` など）は `.gitignore` で除外してあります。
骨（`castle/`）と肉（`instance/`）の分離は、リポジトリの中でも守っています。

## 構成

```
castle/            骨。どの企業でも同じ。個人時間で作ったもの
  schema.sql         共通の骨（records）＋生成列＋取り込みログ
  app/
    normalize.py     汚いCSVを読む（文字コード判定・列名の揺れ・日付書式）
    config.py        部門マスタ。ベンダーごとの部門名の対応表
    db.py            castle/ と instance/ の分離をここで担保
    import_csv.py    入口①：既にあるもの（ベンダーCSV）を骨に載せる
    build_dashboard.py  出口③：判断に必要なものを1枚にする
    serve.py         入口②：薄いローカルサーバ。ダッシュボードと申し送りフォーム
    users.py         利用者と鍵の発行・失効（パスワードは作らせない）
    knowledge.py     知識の泉。1件1事実・上書き原則・棚卸し・表記ゆれ吸収の検索
    backup.py        控えを取る・戻す（検証つき）
    verify.py        判定者：作り直して、機械が正誤を言えることだけ検査する
  templates/
    dashboard.html   出力の型（CSS込み。外部ライブラリ・CDNは使わない）
    note.html        申し送りフォームの型
    login.html       アクセスキーの入力画面
    guide.html       使い方（画面の中の手引き）
    knowledge.html   知識の泉の型

instance/          肉。この企業のデータ。骨とはファイルレベルで分ける
  config.json        会社・部門・目標値・指標の定義
  incoming/          ベンダーのCSVを置く場所
  data.db            SQLite（1ファイル。バックアップはコピーで足りる）
  users.json         利用者と鍵のハッシュ。**このファイルの有無が認証の入り切り**
  backups/           控え（data-YYYYMMDD-HHMMSS.db）
  out/dashboard.html 生成物
  make_sample.py     架空食品商事のサンプルCSVを作る（実データではない）
```

`--instance <パス>` で instance を別の場所に置ける。骨だけ持ち出しても動く。

## 動かす

Python 3.8以上。標準ライブラリだけで動く（外部ライブラリ・CDNなし）。

```bash
python instance/make_sample.py
python castle/app/import_csv.py --kind 売上     instance/incoming/A社*.csv
python castle/app/import_csv.py --kind 労働時間 instance/incoming/B社*.csv
python castle/app/import_csv.py --kind 売上原価 instance/incoming/C社*.csv
python castle/app/build_dashboard.py
```

`instance/out/dashboard.html` をブラウザで開く。

画面とフォームを開くなら、サーバを立てる。`/` は開くたびに作り直すので、常に今のDBを映す。

```bash
python castle/app/serve.py
```

`http://127.0.0.1:8765/`（ダッシュボード）と `/note`（申し送り）。127.0.0.1 にしか口を開かない。

作り直しと検査を一度にやるなら、これ一本で足りる。

```bash
python castle/app/verify.py
```

```bash
python castle/app/import_csv.py --list
python castle/app/import_csv.py --undo 3
```

## 入口が吸収するもの

サンプルCSVは、現実がそうであるようにわざと揃えていない。

| 揃っていないもの | 販売管理（A社） | 勤怠（B社） | 会計（C社） |
|---|---|---|---|
| 文字コード | CP932 | UTF-8（BOM付き） | CP932 |
| 粒度 | 日次 | 日次 | **月次** |
| 日付 | `2026/06/01` | `2026-06-01` | **行に無い**（タイトル行の「2026年7月度」だけ） |
| 単位 | 円 | 時間 | **千円** |
| 部門名 | 加工食品部 | 加工食品／物流ｾﾝﾀｰ／業務用　食材 | **`1010 加工食品`**（コードと同居） |
| 並び順 | 日付順 | 組織順 | 部門コード順 |
| 余計な行 | 先頭のタイトル行、末尾の合計行 | なし | 同左 |

どのベンダーも悪くない。誰も「間」を担当していないだけ。
その「間」が `instance/config.json` の部門マスタで、城が横串たりうる根拠でもある。

対応表に無い部門は**捨てずに件数と名前を報告する**（末尾の合計行はここに出る）。

## 入口②：申し送り

ダッシュボードは「どこが落ちたか」までしか出せない。**「なぜ」は現場にしかない。**
その口が `/note`。書いたものは要確認欄の各件に添えて出るので、
**検知と、現場の言い分が、同じ画面に並ぶ。**

- 追記のみ。書き換え・削除はこの画面からはできない（訂正は新しく書き足す）
- 検証は境界（人の入力）でだけ行う ── 部門・日付・区分・文字数
- 人が書いたものをHTMLに置くのは `note_html()` 一箇所だけ。そこで必ずエスケープする
- 対象日の既定は「今日」ではなく**データのある最終日**（取り込みは必ず遅れるため）

## 知識の泉 ── 数字と並ぶ、もう一本の泉

数字の泉が出すのは「何が起きたか」。知識の泉に貯めるのは「**この会社で、繰り返し効くこと**」。
判断・うまくいかなかった改善・現場のコツ・新人が知らない前提の4種類。

社内wikiが必ず死ぬ理由は3つあり、それぞれに構造で答えている。

| 死ぬ理由 | 構造での答え |
|---|---|
| 書式が自由すぎて後から引けない | **1件1事実。** 本質は一行（120字）しか書けない。一行で書けないなら、まだ2つ以上が混ざっている。「なぜ」と「どう使うか」を必須にする |
| 古い知識が現役の顔をして残る | **上書き原則。** 覆った知識は現役から外す（並存させない）。ただし消さない ── なぜ覆ったかが最大の学び。**棚卸し**で180日見直されていないものを名指しする |
| 書いても読まれない | **探しに行かせない。** その部門の数字が落ちた瞬間、ダッシュボードの要確認欄に並ぶ |

新しい理屈ではない。個人の記憶運用で効くと分かっている規範を、そのまま社内の仕組みに移しただけ。

検索は表記ゆれを吸収する（`search-yure` の4段構成）。
「くらうど」「kuraudo」「ｸﾗｳﾄﾞ」「ＣＬＯＵＤ」が同じものに当たる。
英略語のカナ読みだけは自動生成せず、`config.json` の `search_readings` で個別に持つ（読みが多義になるため）。

## 使い方は、READMEではなく画面の中にある

**このREADMEは開発者向け。** 使う人への案内は画面の中に置いてある ──
READMEに書いた＝案内した、にはならないため。

| 置き場所 | 読む人 | 中身 |
|---|---|---|
| ダッシュボード内の「この画面の読み方」 | 役員・部門長 | 数字の意味／3つの比べ方／推定／傾向と単発／内訳の読み分け |
| `/guide` | 運用担当・管理者 | 毎日と月初の手順／申し送りの書き方／鍵／控え／困ったとき |
| `/note` フォーム内 | 現場 | 何を書く欄か、書いたものがどこに出るか |
| `/knowledge` 内 | 全員 | 一行で書けないなら分ける、なぜと使い方が要る理由 |

読み方は **dashboard.html の中に埋め込んである**。
この1ファイルだけを誰かに渡しても、読み方が一緒に付いていく。
`/guide` は**認証の外**に置いてある ── 鍵を持っていない人が「鍵の貰い方」を読めないと詰むため。

## 控え（バックアップ）と復旧

```bash
python castle/app/backup.py                              控えを取る
python castle/app/backup.py --list
python castle/app/backup.py --restore <ファイル> --yes    戻す
python castle/app/backup.py --prune 14 --yes             古いものを消す
```

- **ファイルコピーで済ませない。** WALのせいで、コミット済みでも `data.db` 本体に
  まだ書かれていない行がある。標準の `Connection.backup()` を使うので、
  サーバが動いたままでも取りこぼさない
- **検証していない控えは控えではない。** 取った直後に開き直し、整合性検査と件数の一致を
  確かめてから「取れた」と言う
- **復旧も取り消せる。** 戻す直前にいまのDBを自動退避するので、間違った控えを戻しても戻れる
- 復旧と削除は `--yes` が無ければ実行しない（人が押す側の操作）
- **控えを同じPCの中だけに置かない。** 別ディスクか共有フォルダにも複製すること

## 認証と、操作者の記録

**パスワード認証は自作しない。** 人にパスワードを作らせると、使い回しと弱い文字列が必ず入る。
代わりに長いランダムな鍵をこちらが発行し、本人は一度貼るだけにする。
強度チェックもリセット手続きも要らず、失効は1行消すだけ。

```bash
python castle/app/users.py --add    "農産部長 田中"   # 平文はこの時だけ表示される
python castle/app/users.py --list
python castle/app/users.py --revoke "農産部長 田中"
```

- 保管は **ハッシュだけ**。users.json が流出しても、それだけでは入れない
- **users.json の有無が認証の入り切り。** 無ければ認証なし（127.0.0.1 限定の一人使い）。
  有れば中身が0人でも全員が入れない ── 開いている側に倒さない
- 鍵が確認できたら、申し送りの入力者欄は**入力させない**。記録されるのは名乗りではなく鍵の持ち主

社内網に出すときは、**認証が入っていること**と、**開く意思の明示**の両方が要る。

```bash
python castle/app/serve.py --host 0.0.0.0 --expose
```

`--expose` が無ければ起動を拒否する。鍵が1本あるだけで通すと、
打ち間違いやコピペで機械が社内網に出てしまうため。

## 分かっている制約

- **取り消しに履歴は無い。** `--undo` はそのバッチが書いたレコードを消す。同じ自然キーを上書きしていた場合、前の値には戻らない。戻すには元のCSVを取り込み直す
- **当月の粗利は推定。** 会計は月次でしか締まらないので、直近の確定月の原価率を日次売上に当てている。金額は日割りしない（日ごとの原価は誰も持っていない）
- **粗利率の変化は、月が締まった瞬間に段差で現れる。** 当月内では動かない
- **売上を持たない部門は人時生産性の対象外。** 物流センター・品質保証部・管理部。人時は全社の分母にも入れていない
- **HTTPSではない。** 社内網に出すならプロキシでHTTPSを終端すること。`--expose` はその点を承知したという合図でしかない
- **鍵を貸し借りされたら分からない。** 記録に残るのは鍵の持ち主。技術的には防げないので、ログイン画面にその旨を書いてある
- **閲覧のログは取っていない。** 書き込みは `records.created_by` で追える。見ただけの記録は取らない
